# Full-duplex plan: requirement-by-requirement acceptance audit

**Date:** 2026-09-23. This audit checks every gate in
[the plan](full-duplex-streaming-plan.md) (sections 9–11) against
[the results record](full-duplex-results.md),
[the handoff](full-duplex-handoff-2026-09-23.md) (including "Progress after
resumption" and "Second round") and the committed tree
[`deploy/duplex/evidence/`](../deploy/duplex/evidence/). A status rests only on
retained, committed evidence. Numbers that appear only in the results
document, with raw files that were in the uncommitted
`.runtime/duplex-plan/results/` (deleted in the 10:16 UTC cleanup), count
for at most **Partial**.

## Status vocabulary

- **Met**: the exit evidence the plan names exists in retained evidence, at the population the plan requires.
- **Partial**: some of the named evidence exists, but a named part is missing or exists only at smoke or subset scale.
- **Not met**: the evidence contradicts the requirement, or the work was attempted and failed.
- **Not started**: no attempt is recorded.
- **Not applicable**: used only for C2, which the plan itself withdraws.
- **Deferred**: used only where the plan itself says to defer (DuplexOmni, SALMONN-omni/OmniFlatten).

Adapters, mock conformance, CPU regressions, sidecar flags and smoke runs do
not count toward acceptance (plan §11). All end-to-end timing is
benchmark-**received** audio, not rendered playback, so no requirement for
playback receipts or audible stops is met anywhere.

## Blocking gaps

1. **Rendered playback receipts.** No layer measures what was actually played or stopped. Every interruption, cancellation and first-release item depends on this. Progress: FDB now also reports `playout_yield_latency_no_flush_ms` (`d6ab0070`). It is the yield measured on the recorder's speaker clock for a client that never flushes, which bounds the prefetch blind spot of arrival timing. FDB hold windows and FD-Bench overlap still count by arrival. The benchmark client can now act as a player (`-player`, `1bab9039`): it stops when the server cancels the response it is playing, sends `conversation.item.truncate` with the played position, and records the server's confirmation or refusal. FDB then reports `audible_yield_latency_ms`. Validated on the micro-turn cascade ([E/playback-receipts/20260923-microturn](../deploy/duplex/evidence/playback-receipts/20260923-microturn/)) after fixing sidecar turns that were never reported as cancelled (`d0225ace`): 35 truncations sent and 35 confirmed, audible yield p50 44 ms. Other native sidecars do not yet mark interrupted turns, and there are still no physical-device receipts.
2. **DuplexCascade public end-to-end failure (C1).** Long answers exceed the 180 s deadline and there are task errors. The cascade reference has no passing public run.
3. **A retained micro-turn cascade campaign.** Done for the Qwen3-8B fallback, gated ([E/microturn-voxtral-qwen3-kyutai/20260923T133815Z-8dw16iqd-fdbench](../deploy/duplex/evidence/microturn-voxtral-qwen3-kyutai/20260923T133815Z-8dw16iqd-fdbench/)): 242/293 FD-Bench passes and all FDB categories. It covers one FD-Bench condition, and playback validation is running. Originally: Run the Qwen3-8B fallback or a fixed DuplexCascade at full FDB + FD-Bench scale from a clean checkout, and commit the traces.
4. **Gated native reruns.** Every retained native campaign ran ungated. Rerun PersonaPlex gated, and complete the queued gated MiniCPM-o campaign.
5. **FD-Bench coverage.** Native campaigns cover 1 of 21 conditions (293 of 6,147 conversations).
6. **Tool correctness in public sessions (N2).** Progress: `openrealtime bench toolcall` (`48b3a30d`) runs ten spoken tool requests, two with corrections, and checks one executed call, correct arguments and the spoken result; first cascade run 8/10 ([E/toolcall/20260923-cascade](../deploy/duplex/evidence/toolcall/20260923-cascade/)): one correction produced a fabricated result with no tool call, and one was misheard and split into a wrong call.
