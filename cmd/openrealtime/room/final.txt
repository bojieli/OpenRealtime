Choose one act for a FINAL transcript. Examples: speaker is someone else in
the room and says "I looked in the fridge and there was not any" -> listen.
Speaker is someone else in the room and says "Can you put it on the list
tomorrow?" -> listen. Apply the first matching rule:

1. If agent output is queued or audible, first determine the addressee and
   whether the speaker is taking the floor. An explicit floor-taking or
   topic-shift request directed to the agent is stop-speaking. A vocative
   naming or role-addressing somebody else is side speech and is
   keep-speaking, even when an early speaker estimate says user. A pure
   one- or two-token acknowledgement is also keep-speaking. Otherwise,
   keep-speaking when the agent deliberately interrupted or spoke through
   this same utterance and the speaker merely continued it. The block
   separates what the user has already heard from what is written and not
   yet audible; only the first is something they were told, and stopping is
   cheapest when the point of the turn is already in it. A distinct
   recording, correction, or new request is stop-speaking.
   When the runtime says output was triggered by an earlier revision of
   this same transcript stream, an unchanged final transcript is always
   keep-speaking. Example: output triggered on "ship it by the thirteenth"
   plus the same final words -> keep-speaking; "sorry, I mean the third"
   in the current words -> stop-speaking.
2. For a recorded menu: act-silently only when the current words contain
   both a digit and the option label matching the user goal; every nonmatch
   is listen. A request to begin the call is listen.
3. If the speaker is someone else in the room: obey an in-force standing
   rule whose condition occurs now; otherwise listen, even for a direct
   question or command. Never answer them. An explicit vocative naming or
   role-addressing somebody else is stronger addressee evidence than an
   early speaker-is-user estimate, so side speech remains listen.
4. A request establishing behavior for a future event is listen, especially
   when it says nothing else. This remains listen when Deepgram split the
   request and the current fragment sounds imperative: "after fifteen
   seconds" followed by "ask whether I am still there" is one future rule,
   not a request to ask immediately.
5. If a partial already handled this occurrence, listen; if a required count
   or translation was missed, answer. In particular, with a standing rule
   to translate a Mandarin-speaking colleague into English, final Chinese
   speech such as "你好，很高兴见到你" is answer, not listen.
6. A completed question or request addressed to the agent is answer. This
   includes an explicit topic-change request such as asking to talk about
   something else. Otherwise listen.
